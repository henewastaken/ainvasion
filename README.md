# World Domination

A turn-based, networked multiplayer world domination strategy game set in Europe.
Players conquer or diplomatically annex adjacent countries, collect resources, and research
new technologies. AI narrates every event and determines outcomes.

Inspired by a mix of **Civilization** (empire building, resources, research) and **D&D**
(AI-generated narrative outcomes, item loot, probabilistic resolution).

---

## Quick start

```bash
# 1 — Backend
cd backend
python3 -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env
uvicorn main:app --reload
# API docs → http://localhost:8000/docs

# 2 — Frontend (new terminal)
cd frontend
cp .env.example .env
npm install
npm run dev
# App → http://localhost:5173
```

## Game rules

| Rule | Detail |
|---|---|
| **Turn structure** | Players take turns in join order. One action per turn. |
| **Actions** | Attack a neighbour (war or diplomatic) **or** research an item — not both. |
| **Adjacency** | You may only target countries that border your current empire. |
| **Resources / items** | Found as loot after battles or unlocked by research. Used to influence outcomes. |
| **Country properties** | Each country has `army_strength`, `morale`, a favourite resource (boosts defenders) and a hated resource (weakens defenders). These are generated by AI at game start. |
| **Victory** | Last player with an empire, or first to own all countries. |

## Turn flow

```
Player clicks adjacent country
        │
        ▼
Frontend: POST /game/{id}/action  (or /research)
        │
        ▼
Backend validates:
  • Is it this player's turn?
  • Has the player already acted?
  • Is the target actually adjacent?
  • Are claimed items in inventory?
        │
        ▼
ai/llm_client.py: resolve_attack() or resolve_research()
  (mock today — replace with LLM call)
        │
        ▼
game_engine.py:
  apply_action_result() / apply_research_result()
    → update ownership, army strength, inventory
  advance_turn()
    → rotate current_turn_player_id
  check_victory()
    → set status="finished" if won
        │
        ▼
state_manager.update_state()
        │
        ├─► HTTP response → ActionResponse / ResearchResponse  (story, items, army strengths)
        │
        └─► ws.broadcast()  →  { type: "state_update", state: GameState }
                 │
                 ▼
        All connected players receive updated GameState via WebSocket
        Frontend re-renders map, panels, story log
```

### Game start flow

```
Creator: POST /game/create → game_id, player_id
Others:  POST /game/join/{game_id} → player_id
Creator: POST /game/start/{game_id}
         │
         ▼
ai/llm_client.generate_country_resources()
  Assigns favourite_resource + hated_resource to every country
         │
         ▼
ws.broadcast({ type: "game_started", state })
         │
         ▼
All players transition to game view; first player's turn begins
```

## Integrating a real LLM

All AI logic is isolated in `backend/ai/llm_client.py`. The three functions currently return
deterministic mock data and are clearly marked `# TODO`. To wire up a real model:

1. Pick a provider — HuggingFace Inference API, a local Ollama endpoint, or any OpenAI-compatible API.
2. Add `httpx` (or the provider's SDK) to `backend/requirements.txt`.
3. Fill in each `# TODO` block:
   - Load the matching prompt template from `ai/prompts.py`.
   - `str.format(**kwargs)` it with the function arguments.
   - `POST` the prompt to the model API.
   - Parse the JSON from the model's response.
   - Return it as the typed dataclass already defined in the function signature.
4. No other files need changing.

## Known limitations / future work

- **Persistence**: game state is in-memory. A restart loses all sessions. Add a database layer (SQLite to start) to fix this.
- **Authentication**: player IDs are trust-based. Add token-based auth for production.
- **Map**: the frontend uses a placeholder rectangle grid. Real SVG Europe paths should replace `src/data/placeholderMapData.ts` post-MVP.
- **LLM integration**: all AI functions are mocked. Wire in a real model to unlock narrative generation.
- **Mobile layout**: the three-column game layout is not optimised for small screens.
